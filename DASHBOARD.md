## Промпт

> Сделай веб-дашборд Earnings Engine в `web/` (Next.js, только чтение) по `DASHBOARD.md`. Стиль — современный светлый интерфейс (раздел 2), без лишнего. Фронтенд ничего не считает: все числа, формулы, сортировки и статусы приходят готовыми из API. Показывай только то, что перечислено в этом файле. Если для экрана не хватает поля в API — добавь эндпоинт в `api/` с расчётом на бэкенде, не считай на фронте.

## 1. Принципы

1. **Фронтенд — только отображение.** Никаких формул, вероятностей, сумм, сортировок по расчётным полям, процентов. API отдаёт готовые строки и числа с форматированием (`"+4,8%"`, `"897.00"`, `"16:30 МСК"`).
2. **Только важное.** На каждом экране один вопрос и ответ на него. Никаких признаков модели, весов, β, Brier на рабочих экранах — они только в «Системе».
3. **Одно действие — одно место.** Что сделать сейчас — всегда наверху экрана «Сегодня».
4. **Пусто — значит пусто.** Нет данных — строка «нет событий», а не нули и прочерки в таблице.
5. **Только чтение.** Ордера не ставятся из дашборда. Кнопки только навигационные.

## 2. Стиль: современный светлый

Решение заказчика 2026-10-14: вместо стиля «веб 2000-х» — современный светлый интерфейс.

| Элемент | Правило |
|---|---|
| Фон | страница `#F6F7F9`, карточки и таблицы — белые с рамкой 1 px `#E2E8F0`, скругление 12 px |
| Текст | `#0F172A`; второстепенный — `#64748B`; шрифт Inter (латиница и кириллица), 14 px; числа — моноширинные цифры (`tabular-nums`) |
| Ссылки | `#2563EB`, подчёркивание при наведении |
| Акцент «действие» | `#DC2626` (только для того, что требует действия); блок действия — светло-красная карточка |
| Плюс / минус | `#059669` / `#E11D48` |
| Меню | вкладки с подчёркиванием активной; вторичные вкладки — переключатель-«таблетки» |
| Полоса счёта | плитки: подпись мелким серым, значение крупно |
| Таблицы | шапка мелким серым на светлом фоне, разделители строк, подсветка при наведении |
| Ширина | колонка до 1200 px по центру; на телефоне — 100%, меню прокручивается в строку, таблицы прокручиваются внутри блока |
| Анимации | нет |
| Время | везде две зоны: `09:30 ET / 16:30 МСК` |

Шапка сайта: слева `Earnings Engine`, справа плашки «Рынок» и статуса (`СИСТЕМА ОК` с зелёной точкой) и время `13.10.2026 · 11:42 ET / 18:42 МСК`. При сбое — `СИСТЕМА: СБОЙ DATA_MASSIVE` красным.

## 3. Меню и вкладки

Меню — горизонтальная полоса серых вкладок под шапкой. Внутри разделов — вторичные вкладки меньшего размера.

```
┌────────────────────────────────────────────────────────────────┐
│ EARNINGS ENGINE   РЫНОК: ЖЁЛТЫЙ · VIX 22   СИСТЕМА ОК_ · 11:42 ET/18:42 МСК │
├────────┬────────┬────────┬────────┬──────────┬──────┬─────────┐            │
│СЕГОДНЯ │ НЕДЕЛЯ │ СДЕЛКИ │ ЖУРНАЛ │ КОМПАНИИ │ СЧЁТ │ СИСТЕМА │            │
├────────┴────────┴────────┴────────┴──────────┴──────┴─────────┴────────────┤
│ [PAPER] БАЛАНС $103 450 · СВОБОДНО $81 200 · В СДЕЛКАХ $22 250 (21,5%)       │
│ P&L СЕГОДНЯ +$412 (+0,4%) · МЕСЯЦ +$1 840 (+1,8%)                          │
│ РИСК 3,1% · ПРИ ВСЕХ СТОПАХ ПРОСАДКА 7,4% / 10%                             │
└────────────────────────────────────────────────────────────────────────────┘
```

**Полоса счёта** — всегда видна под меню на любом экране. Шесть чисел, все с бэкенда:

| Поле | Что значит |
|---|---|
| БАЛАНС | стоимость счёта: деньги + текущая стоимость позиций |
| СВОБОДНО | деньги, доступные для новых сделок |
| В СДЕЛКАХ | текущая стоимость открытых позиций, $ и % от баланса |
| P&L СЕГОДНЯ | реализованный + нереализованный за день, $ и % |
| P&L МЕСЯЦ | то же с начала месяца |
| РИСК | сумма максимальных убытков открытых позиций (до стопов / по премиям), % от баланса |
| ПРИ ВСЕХ СТОПАХ ПРОСАДКА | просадка от пика баланса, если все открытые позиции закроются по стопам, против порога ручного разбора `risk_limits.drawdown.manual_review` (10%). `tone=action`, когда худший случай достигает порога |

Лимита на суммарный риск нет (решение заказчика 2026-10-13), поэтому РИСК не сравнивается с лимитом. Вместо этого показан худший случай против единственного правила, которое открытый риск может нарушить, — порога просадки 10% (SPEC §10).

Слева метка режима счёта: `[PAPER]` или `[REAL]`, переключатель — ссылка рядом. Paper и Real никогда не суммируются.

**Плашка РЫНОК** в шапке: уровень Black Swan (ЗЕЛЁНЫЙ / ЖЁЛТЫЙ / ОРАНЖЕВЫЙ / КРАСНЫЙ) и VIX. Цвет — с бэкенда.

| Раздел | Вопрос, на который отвечает | Вторичные вкладки |
|---|---|---|
| СЕГОДНЯ | Что мне делать сейчас? | — |
| НЕДЕЛЯ | Какие отчёты на неделе стоит торговать? | Топ · Все события |
| СДЕЛКИ | Что у меня открыто и что с ним? | Открытые · Закрытые |
| ЖУРНАЛ | Что система решила по каждому отчёту и почему? | Все · Вошли · Пропуски |
| КОМПАНИИ | Что известно о компании и секторе? | Сектора → Компания: Коротко · Новости · Отчёты · Финансы · История отчётов |
| СЧЁТ | Сколько я заработал и насколько система надёжна? | Итоги · Показатели · Путь к Real |
| СИСТЕМА | Работает ли система и как она учится? | Статус · Модели · Плагины |
| НАСТРОЙКИ | Что сломалось и почему? | Логи ошибок |

## 4. Экраны

### 4.1 СЕГОДНЯ (главная)

Четыре блока сверху вниз, без ничего лишнего:

0. **ИЗМЕНИЛОСЬ** — только если есть изменения с прошлого визита: сигнал отменён, дата отчёта перенесена, стоп подтянут, новая версия весов. До 5 строк, кнопка «понятно» скрывает блок.
1. **СЕЙЧАС** — красная рамка, если есть действие. Одна строка на действие: время, тикер, что сделать, ссылка на карточку. Нет действий → «Действий нет. Следующее: 15:30 ET — вход GS».
2. **ОТЧЁТЫ СЕГОДНЯ** — таблица: тикер · время (BMO/AMC) · решение (ВХОД / ПРОПУСК / ЖДЁМ) · режим · одна строка причины.
3. **ОТКРЫТЫЕ ПОЗИЦИИ** — таблица: тикер · режим · P&L % · стоп · следующий шаг.

```
СЕЙЧАС
┌──────────────────────────────────────────────────────────┐
│ 15:30–15:55 ET │ GS │ ВХОД режим B: акция + коллар │ [карточка] │
└──────────────────────────────────────────────────────────┘
ОТЧЁТЫ СЕГОДНЯ
Тикер  Время  Решение  Режим  Причина
JPM    BMO    ПРОПУСК  —      EDGE_LOW: преимущество 1,2% < порога
C      BMO    ПРОПУСК  —      PRE_RUN: +7,4% за 3 дня без причины
ОТКРЫТЫЕ ПОЗИЦИИ
Тикер  Режим  P&L     Стоп    Дальше
NVDA   C      +6,0%   921.00  трейлинг, пересчёт 16:05 ET
```

### 4.2 НЕДЕЛЯ

**Топ** — 5 событий из `GET /api/week`, уже отсортированных бэкендом по ожидаемой прибыли с учётом размера. Колонки: № · тикер · дата и время · режим · конструкция · ожидаемая прибыль ($) · уверенность (%). Больше ничего.
**Все события** — остальные отчёты недели: тикер · дата · статус · код причины пропуска (если есть).

**Терминал** (блок под топом) — когда мне быть у терминала на неделе: день · время ET / МСК · тикер · что делать (вход / решение режима C / выход). Только моменты, где нужно действие человека.

### 4.3 СДЕЛКИ

**Открытые** — тикер · режим · состояние (ARMED / OPEN / C_MODE / CLOSING) · вход · текущая цена · P&L % · стоп · следующий шаг. Клик → карточка сделки: тот же текст, что в Telegram, плюс история переходов (время · из → в · причина).
**Закрытые** — тикер · даты · режим · итог % · итог $ · причина выхода. Внизу одна строка итога, рассчитанная на бэкенде: «Сделок 12 · прибыльных 7 · итог +$1 840».

Над таблицами — строка доверия: «Калибровка: система говорит 65% → сбывается 61% · Издержки Paper против реальности: расхождение 8%». Если расхождение выше порога из `thresholds.yaml` — строка красная.

### 4.4 ЖУРНАЛ

Вверху — итог фильтров за сезон: «Пропуски сэкономили $2 100 · упустили $900». Под ним маленькая таблица по кодам причин: код · сколько раз · сэкономлено $ · упущено $.

Ниже — по одной строке на каждый состоявшийся отчёт: дата · тикер · решение (ENTERED / SKIPPED / CANCELLED / DATA_FAIL) · коды причин · результат теневой сделки (для пропусков). Фильтр вкладками: Все · Вошли · Пропуски. Без графиков.

### 4.5 КОМПАНИИ

**Сектора** — список секторов: название · тренд (↑ / → / ↓) · одна строка резюме · число компаний · ближайший отчёт. Клик → компании сектора: тикер · название · дата отчёта · статус в очереди.

**Профиль компании** — пять вкладок:

| Вкладка | Что показывать | Чего не показывать |
|---|---|---|
| Коротко | 3–5 строк о бизнесе, сегменты, место в секторе, дата следующего отчёта | признаки модели |
| Новости | события с прошлого отчёта: дата · тег (менеджмент / регуляторика / M&A / конкуренты) · заголовок-ссылка | полные тексты |
| Отчёты | список отчётов со ссылками на источник; резюме аудита последнего отчёта (ожидали / вышло по сегментам, guidance, риски) | сырые таблицы отчётности |
| Финансы | 6–8 ключевых показателей за 8 кварталов одной таблицей (выручка, маржа, EPS, сегменты — что задано для сектора) | мультипликаторы, если их нет в профиле сектора |
| История отчётов | Earnings Track: дата · ожидание EPS · факт · сюрприз % · ожидаемое движение · фактическое · **причина реакции** · решение системы | вероятности модели |

### 4.6 СЧЁТ

**Итоги** — таблица по периодам (сегодня · неделя · месяц · сезон · всё время): P&L $ · P&L % · сделок · прибыльных %. Под таблицей один график — кривая баланса по дням (ступенчатая линия без заливки и сглаживания). Paper и Real — отдельно, переключатель сверху.

**Показатели** — одна таблица, значения с бэкенда, за сезон и за всё время:

| Показатель | Зачем |
|---|---|
| Доходность, % | итог |
| Win rate, % | доля прибыльных сделок |
| Средняя прибыль / средний убыток, $ | асимметрия |
| Profit factor | сумма прибылей / сумма убытков; < 1 — система теряет |
| Ожидаемая прибыль на сделку, $ | главный показатель стратегии |
| Sharpe | доходность с поправкой на риск |
| Максимальная просадка, % и текущая просадка, % | против порогов 10% и 15% |
| Издержки всего, $ и % от прибыли | сколько съедает брокер и спред |
| P&L по режимам A / B / C, $ | какой режим зарабатывает |
| P&L по источникам: направление / волатильность / спад IV, $ | откуда деньги |

**Путь к Real** — прогресс по критериям перехода из Paper: `СДЕЛОК 34/50 · SHARPE 1,2/1,0 ✓ · ПРОСАДКА 6%/15% ✓ · ДНЕЙ 41/30 ✓`. Невыполненный критерий — красным.
Критерии (решение заказчика 2026-10-13, хранятся в `thresholds.yaml`): ≥ 50 сделок, Sharpe > 1,0, максимальная просадка < 15% (SPEC §14, фаза 4), ≥ 30 дней в Paper. Не путать с SPEC §14 «первые 30 дней × 0,5» — это размер позиций уже после перехода на Real.

### 4.7 СИСТЕМА

**Статус** — источники данных (Massive, Finnhub, Alpha Vantage, брокер, Telegram, сторож): ОК / СБОЙ · время последнего успешного обновления. Последние 20 сообщений «СИСТЕМА».
**Модели** — версия каждой из трёх моделей · дата обучения · Brier на отложенной выборке · принята / отклонена. Одна таблица.
**Плагины** — агенты и стратегии: имя · версия · стадия (shadow / paper / live_small / live) · вклад за сезон (одна цифра с бэкенда) · помечен к отключению да/нет.

### 4.8 НАСТРОЙКИ

Решение заказчика 2026-10-14. **Логи** — последние 100 записей журнала задач, от новых к старым: время ET / МСК · статус · задача (`options`, `calendar-daily` …) · тикер · стадия · тип · текст · кнопка «скопировать».

- Ошибка красным, пока не решена; у нерешённой — кнопка «скопировать» (готовый текст для отправки на исправление: что упало, где полный лог).
- Ошибка **решена**, когда та же задача потом отработала: у задачи события — тот же тикер и стадия (успех другого тикера чужую ошибку не решает), у ежедневной задачи — её следующий успешный запуск. Решённая ошибка — зелёным «решено <когда>», без кнопки; в журнал пишется одна строка «Решено: NFLX T-7 — задача отработала успешно».
- Повторить упавшую задачу с тем же моментом оценки: `make rerun-job ARGS="NFLX T-7 options"`.

Источник — таблица `error_log`: её пишут диспетчер задач событий и ежедневные задачи (календарь, консенсус, архив); секреты вычищаются при записи. Шапка показывает «СИСТЕМА: СБОЙ …», пока за сутки есть нерешённые ошибки; плашка ведёт сюда.

## 5. API (все расчёты на бэкенде)

| Эндпоинт | Отдаёт |
|---|---|
| `GET /api/status` | статус системы и источников, уровень РЫНОК (Black Swan + VIX) |
| `GET /api/account?mode=paper\|real` | полоса счёта: баланс, свободно, в сделках, P&L сегодня и месяц, риск против лимита |
| `GET /api/account/summary?mode=…` | «Счёт»: итоги по периодам, показатели, кривая баланса, путь к Real |
| `GET /api/changes?since=<ts>` | блок ИЗМЕНИЛОСЬ |
| `GET /api/today` | блоки СЕЙЧАС, ОТЧЁТЫ СЕГОДНЯ, ОТКРЫТЫЕ ПОЗИЦИИ |
| `GET /api/week` | топ-5 и все события недели, уже отсортированные |
| `GET /api/trades?state=open\|closed` | сделки + строка итога |
| `GET /api/trades/{id}` | карточка + история переходов |
| `GET /api/journal?filter=all\|entered\|skipped` | журнал решений + итог фильтров и таблица по кодам причин |
| `GET /api/week/terminal` | расписание действий человека на неделю |
| `GET /api/sectors` · `GET /api/sectors/{id}` | сектора и компании сектора |
| `GET /api/companies/{ticker}/{tab}` | вкладка профиля: `overview`, `news`, `reports`, `financials`, `track` |
| `GET /api/system/models` · `GET /api/system/plugins` | таблицы «Системы» |
| `GET /api/system/errors?limit=` | «Настройки → Логи ошибок» (1–500, по умолчанию 100) |

Правила API для дашборда:
- Все числа приходят двумя полями: значение для логики (`value`) и готовая строка для показа (`display`). Фронт показывает только `display`.
- Цвет приходит с бэкенда полем `tone`: `positive` / `negative` / `action` / `neutral`. Фронт только сопоставляет `tone` с цветом из раздела 2.
- Время приходит строкой `"09:30 ET / 16:30 МСК"`.
- Источник баланса: в MVP (ручной брокер) — стартовый капитал из `thresholds.yaml` + подтверждённые исполнения; после подключения брокера — данные `BrokerAdapter.positions()` и баланс счёта; расхождение с расчётом системы выше порога из `thresholds.yaml` (старт 0,5%) → сообщение «СИСТЕМА».
- Обновление: полоса счёта, «Сегодня» и «Сделки» опрашивают API в основную сессию и вне её с интервалами из `thresholds.yaml` (старт 60 секунд / 10 минут). Остальные экраны — при открытии.

## 6. Приёмка

- [ ] В `web/` нет арифметики над данными (проверка: поиск `* / + -` над полями ответа API в компонентах — только индексы и разметка).
- [ ] Каждый экран отвечает на свой вопрос из раздела 3 без прокрутки на мониторе 1366×768 (кроме длинных таблиц).
- [ ] Светлая тема, стиль раздела 2: карточки, вкладки с подчёркиванием, плитки полосы счёта, без анимаций.
- [ ] На «Сегодня» действие видно первым и выделено красной рамкой; без действий — строка «Действий нет» и следующее событие.
- [ ] В профиле компании пять вкладок; в «Истории отчётов» есть причина реакции.
- [ ] Признаки, веса и вероятности модели есть только в разделе «Система».
- [ ] При сбое источника шапка показывает «СИСТЕМА: СБОЙ …» красным.
- [ ] Полоса счёта видна на всех экранах; Paper и Real не смешиваются.
- [ ] В «Счёте» все показатели из таблицы раздела 4.6 приходят с бэкенда; кривая баланса — единственный график на сайте.

## 7. Размещение и доступ

Решение заказчика 2026-10-13: дашборд на Vercel, без экрана входа в приложении, видит только заказчик.

Адрес на Vercel по умолчанию публичный: кто узнает ссылку, увидит баланс и позиции. Поэтому доступ закрывается средствами платформы, а не логином в приложении:

1. **Vercel Deployment Protection** — сайт открывается только для аккаунта заказчика в Vercel. Какой уровень защиты доступен на тарифе (в том числе для production-домена), проверить при T19b; если нужного уровня нет — остановиться и спросить заказчика.
2. **Токен между сайтом и API.** `web/` запрашивает FastAPI только на сервере (Server Components / Route Handlers) с секретным токеном из переменных окружения Vercel. Браузер к FastAPI не обращается, токен в браузер не попадает. FastAPI отвечает только на запросы с токеном.

Заказчику это ничего не добавляет, кроме входа в свой аккаунт Vercel.
